How It Works

The 4-Stage LangGraph Agent Pipeline

A look under the hood at how queries move from intent classification to synthesized cited answers.

STAGE 01

Intent & Planning

Deconstructs the user query, extracts key entities, and decides the optimal research strategy.

STAGE 02

Intelligent Routing

Checks local KB confidence threshold and temporal triggers to branch into Local RAG, Web Live, or Both.

STAGE 03

Hybrid RRF & Rerank

Dense + BM25 candidates fused via Reciprocal Rank Fusion (k=60) and reranked by a cross-encoder model.

STAGE 04

Synthesis & Citation

Synthesizes evidence into structured markdown with inline [n] references and validates faithfulness score.

Frequently Asked Questions

Everything you need to know about Athena.

Common questions regarding our hybrid RAG architecture, citation grounding, and deployment options.

Standard vector search excels at conceptual similarity but often fails at exact keyword matches, code identifiers, acronyms, and product numbers. Athena runs dual retrieval (dense sentence-transformers + BM25 Okapi sparse index), blends ranks via Reciprocal Rank Fusion (RRF), and applies a cross-encoder reranker for maximum precision.
Yes. Athena is built local-first. Embeddings are generated with on-device MiniLM models, the vector database runs locally on ChromaDB, and LLM inference can be handled via local Ollama models (e.g. Llama 3.2, Mistral, Qwen) or extractive mode with zero external network calls.
During synthesis, the LangGraph agent must reference retrieved chunks using inline markers like [1], [2]. The post-processing stage verifies that all claims correspond to retrieved evidence and computes a faithfulness score representing the percentage of supported claims.
Athena supports PDF documents (with page-level chunk indexing), Markdown files (.md), and plain text (.txt). Ingestion performs incremental fingerprint hashing so unchanged files are never re-processed unnecessarily.
